# EchoMind 场景化评测升级设计

## 已确认的目标

将现有多 Agent 客服升级为可回放、可解释、可比较的场景驱动系统。先修复轨迹与评测一致性，再建立离线场景/实验闭环，最后增加上下文来源、版本及检索策略的可控实验。用户已要求按照上一轮方案直接编写执行计划并实施。

## 架构

- `ChatService.chat()` 是 API 和评测共用入口，包含记忆读取、意图及实体、编排、写回、画像任务管理和完整计时。
- 规则检查业务契约，Judge 结合证据评价语义；不可评估、技术失败、断言失败分别记录。
- 场景 runner 接收每次运行独立的 service factory，测试用户、Redis key、Chroma collection、知识、工具和监控对象均与线上隔离。
- Langfuse 作为可选观测导出；禁用、缺少依赖或导出失败不影响客服请求。应用侧默认只导出脱敏或结构元数据，全文内容需显式开启。
- 现有 Redis/Chroma 保持默认行为；增加 ContextRef 来源/版本、记忆变更审计和有明确开关的检索策略。OpenViking 全量迁移及线上影子服务为可选后续工作。

## 约束与验收

1. 保留 `/chat` 和旧 `/eval/run` 响应字段；仅添加兼容字段。`latency_ms` 表示完整请求耗时，另保留编排耗时。
2. 工具实际执行与业务完成分开；当前工具不执行退款、订单修改或真实建单。
3. baseline 仅显式提升；数据、知识和裁判保持同快照，代码/模型/Prompt/Skills/检索只有显式声明为实验变量时允许不同，其余变化拒绝比较。
4. Judge 缺字段、非有限值、越界、超时和解析失败不得以 0.5 混入均值。任务通过要求所有必选断言通过；不可评估不得显示为通过。
5. 首批 120 条人工可检查的合成场景分八组，覆盖十九类意图；明确标注为待业务确认，不宣称生产准确率。
6. 离线默认只校验数据与运行无网络测试。真实模型回放必须显式选择 live 并配置模型，禁止静默触发付费调用。
7. 每次实验记录 dataset、模型、Prompt/Skills、知识、代码、Judge、检索策略版本；所有 attempted 都进入总数，错误/超时/invalid 单列。
8. 测试不能依赖真实模型、Redis、Chroma 或 Langfuse；另提供 live 联调步骤，并明确未执行项。
9. 只修改 `github-release/EchoMind`；参考仓库和原始资料不改。所有工作保留在本地分支，不 push、不部署。
10. 跨会话初始历史必须归档为可召回记忆；用证据ID断言实际召回，语义裁判另检查具体历史事实，移除记忆的反向测试必须失败。

## 方案选择

采用“EchoMind 场景执行器 + 可选 Langfuse + OpenViking 设计借鉴”。纯自建会重复实验管理能力；同时替换上下文存储会混合过多变量，缺少迁移收益证据。新增能力必须能关闭，并通过固定输入的配对实验比较。

## 实施范围

本轮实施 P0、P1、P2 的代码、数据、界面、测试与运行文档。第三方服务真实联调、业务人员确认标注、生产权限系统与 OpenViking 迁移不属于已验证交付；必须在执行记录里单列。
